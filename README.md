# Habit Seasons

个人、手机优先、本地优先的习惯 PWA。零运行时依赖、无账号、无后端、无分析追踪。使用 Vite 开发与构建，源码位于 `src/`，发布产物生成到 `dist/`。

正在逐步迁移到 React。本阶段完成构建工具接入，界面仍使用原生 JavaScript。学习说明与练习见 [第 1 课：Vite](docs/react-migration-01-vite.md)。

## MVP

- 进行中：今日执行、积分、每期进度和详情；支持展开记录 / 快速打卡列表切换，视图偏好保存在当前设备。
- 习惯模板：创建、编辑、停用/恢复、开始新一期、历史期数。
- Goals：独立量化目标、进度事件、里程碑奖励、暂停/放弃/恢复与历史。
- 奖励：全局余额、一次性奖励与价格、删除未兑换奖励、确认兑换、兑换历史；再次兑换需新建奖励。
- 历程：完成/提前结束的周期、完成过的习惯、日期、执行记录与完成率。
- 数据：JSON 全量导入/导出、版本/引用/积分一致性校验、覆盖前确认。
- PWA：主屏幕安装、应用图标、离线缓存；首次访问需要网络。

## 数据模型（schemaVersion: 4）

| 集合 | 内容 |
| --- | --- |
| templates | 名称、图标、难度、单次积分、停用标记 |
| cycles | 模板 ID、开始/计划结束日期、模板设置快照、本期执行频率、可选备注、单次积分快照、周奖励积分、达标比例（旧周期为 null）、状态、实际结束日期 |
| checkins | 周期 ID、本地日期、当次积分；周期 + 日期唯一 |
| rewards | 一次性奖励实例：名称、积分价格、旧版收起标记；是否已兑换由 redemptions 判断 |
| redemptions | 奖励 ID、兑换时名称/价格、时间 |
| goals | 固定目标总量、单位、完成奖励、状态、截止日期、进度事件及修改记录、百分比里程碑、生命周期与奖励流水 |

余额 = 全部打卡积分 + 已达标周奖励 + 当前有效的 Goal 里程碑与完成积分 − 全部兑换价格，不重复存余额。更改模板和奖励不改写历史。采用 localStorage 原子保存一个版本化 JSON；写入失败不更新内存，多标签冲突先刷新再重试。不做永久连续打卡天数。

## 明确的规则

- 每期单独选择每天、每周指定日期或每周 X 次；每期每天最多打卡一次，支持当天打卡，以及本周一至昨天的补打卡（按设备本地日期）。补卡仅限未归档周期内的可执行日，与当天打卡共享每周次数上限，获得相同积分；不支持撤销补卡。
- 进行中常驻周一至周日的整周进度与剩余次数，覆盖所有执行频率。今日打卡、撤销、补卡和周一换周会立即重新计算。快速视图的圆形勾选框和名称完成色仅表示今天，本周次数单独显示。
- 每周 X 次按周一到周日统计（1–7 次），执行日自由安排。首尾不足一周时目标为 min(X, 可执行天数)。达到当周目标后不能额外计分，未完成次数不跨周累计；详情中的截至本周目标包含当前整周目标。
- 模板只保存名称、40 种图标之一、难度与积分，不保存频率。v1 本地数据和备份自动升级到 v2，以每个旧周期快照中的频率为准，保留历史和积分。
- 同一模板同一时间只允许一个未归档周期；支持未来开始；首尾日期均包含，最长 10 年。
- 1/4/6/12 月为日历月，结束日取下一个月边界的前一天；月底按目标月最后一天夹取。
- 新周期默认达标比例 90%，开始时可设为 1–100 的整数；所需次数为 ceil(原计划次数 × 比例 / 100)，不使用显示完成率的四舍五入结果判定。到期不自动归档，仍可补本周漏卡；用户结束并归档时，系统判断为「已完成」或「未达标」，两者都保留历史和积分；提前结束时，零打卡的周期直接删除，不计入历史期数，模板保留；有打卡的周期单独归档，仍保留已得积分。
- 完成率 = 打卡次数 / 整个原计划的应执行次数。提前结束不缩小分母，详情另显示截至结束时的应执行次数。
- 每条奖励只允许兑换一次，兑换后从待兑换列表移入兑换记录。旧版备份无需更换格式：未兑换奖励继续可用，已兑换奖励仅保留历史；旧版同一奖励的多次兑换记录和当时的名称、价格完整保留，积分余额不变。
- 开始一期时可覆盖本期单次积分（1–1,000），并开启可选周奖励（默认关闭，开启时默认等于单次积分，可自定义 1–1,000,000）。规则开始后固定，不随模板修改。每周达成全部计划时立即获得一次周奖励，补卡也可触发；首尾不足一周按该周实际计划次数达标，奖励仍为设定的固定数额。
- 周奖励由不可变的本期规则及打卡记录按周期/周计算，不重复存余额；每周最多一笔，历年记录及备份均可重建。整期未达标或提前结束不撤回已经获得的周奖励。
- 今日打卡可撤销；如果导致该周不达标，基础积分与周奖励一并扣回。若积分已消费且当前余额不足，则不能撤销。兑换确认后保留，不提供取消兑换。
- 模板可停用；未兑换奖励可编辑或确认后永久删除，不扣积分；旧版已收起奖励仍可恢复或删除。兑换后不可编辑、删除、恢复或再次兑换。再次兑换同名奖励须创建独立实例，不删除历史；归档后记录只读。
- v1/v2/v3 备份自动升级到 v4；旧周期保留原单次积分、状态、无周奖励、无达标比例。旧周期依旧在到期后由用户确认完成，不按新阈值重新判定。
- 首次使用为空白状态，不预置模板、奖励、目标或任何记录；已有数据和导入备份不会被清空。
- 不做登录、后端、云同步、推送、RPG、任意复杂重复规则或任务树。

## Goals 规则

- 支持从 40 个图标中选择目标图标；创建后可在详情中更换，历史目标同样支持。旧版目标默认显示靶心图标。
- Goal 直接创建，无模板、子任务或 Habit 关联。必须设置标题、正数总量和单位；总量、单位与完成奖励创建后固定。截止日期可选。
- 进度与百分比支持最多 6 位小数；计算使用百万分之一整数与精确百分比比较，避免小数累加提前完成。总量上限 10 亿，每个目标最多 50 个不重复百分比里程碑。
- Active 可增加正数进度，不允许超过总量。Paused、Abandoned 需先恢复再新增。所有状态均可修正历史事件的正数值，原值、每次修正和时间一直保留；不支持负数或删除进度事件。
- 0% < Milestone < 100%；每个里程碑和完成奖励为 0–1,000,000 的整数积分。一次进度可跨越多个里程碑，100% 自动完成。Goal 积分可直接兑换现有 Rewards，Habit 不会自动改变 Goal。
- 尚未达成的里程碑可新增、编辑和删除；设置到已有进度以内时立即发奖并锁定。曾经达成的里程碑永久锁定，包括奖励已回滚的情况。
- 历史修正会重新结算奖励。低于阈值扣回积分，重新达到再补发；固定奖励配置和奖励流水防止重复累计。余额不足以扣回时整次修改失败，进度、历史、状态和积分都不改变。
- 修正后的进度达到 100% 时自动 Completed；Completed 降到 100% 以下时恢复 Active。暂停/放弃中的历史修正若仍未完成，保留原状态；修正到 100% 则自动 Completed。
- 暂停、放弃和恢复保留进度、积分和全部历史。Goals「当前」显示 Active / Paused，「历史」显示 Completed / Abandoned。状态变化和历次完成时间保留在生命周期记录中。
- 截止日期到期只显示超期，不改变状态或积分。用户可修改或清空截止日期，每次变更保存原值、新值和时间。暂停不自动延期。
- 备份包括所有 Goal、进度修改、截止日期、状态和积分流水；导入时校验历史连续性、里程碑锁定、累计进度、奖励和余额。新版本继续使用原 localStorage 键，v1/v2/v3 数据自动升级，导出文件数据格式为 v4。

## 运行和验证

需要 Node 22.12+，推荐 Node 24 LTS。首次运行先安装锁定的开发依赖：

```sh
npm ci
npm run dev
```

验证业务规则、生成生产网站并验证离线产物：

```sh
npm test
npm run build
npm run test:build
```

开发时打开 http://127.0.0.1:5173 。`npm run preview` 在 http://127.0.0.1:4173 查看上一次构建生成的网站。开发环境不注册 Service Worker；生产构建保留离线能力。手机安装需要 HTTPS 托管；手机访问电脑普通 HTTP IP 不满足 Service Worker 安全上下文要求。

数据属于固定网址、浏览器/安装入口；换域名、换设备、清除网站数据前先导出。iOS 安装请使用 Safari 分享菜单的「添加到主屏幕」。本地存储不是长期备份，建议每月导出并另存一份。

先执行 `npm run build`，再静态部署生成的 `dist/` 全部文件。`dist/` 不加入版本控制，也不要手动修改；离线资源清单和缓存版本根据构建内容自动生成。新缓存就绪后可点击更新（先保存/关闭表单），也可以关闭全部旧页面后重新打开，避免离线混用不同版本。不将个人数据加入应用缓存或源码。

## GitHub Pages

仓库包含 `.github/workflows/pages.yml`。在 GitHub 仓库的 Settings → Pages 中，将 Source 设置为 GitHub Actions。推送到 `main` 或手动运行工作流后，自动安装锁定依赖、执行核心测试、构建并验证离线资源，再发布 `dist/`；不会上传浏览器本地记录。

所有应用资源、安装入口和 Service Worker 均使用相对路径，支持项目网站的 `/仓库名/` 子路径。离线缓存按网站路径隔离，缓存版本在构建时自动生成。离线行为的源码模板位于 `pwa/sw.js`。

发布成功后，以工作流输出的 HTTPS 地址为准：

- iPhone：Safari 打开 → 分享 → 添加到主屏幕。
- Android：Chrome 打开 → 菜单 → 安装应用 / 添加到主屏幕。
- 迁移现有记录：在电脑本地应用中导出 JSON，通过 AirDrop 或文件传到手机，在安装后的应用中导入。

`127.0.0.1` 只指向当前设备，不能把电脑上的这个地址直接放到手机访问。GitHub Pages 是公开的网站入口，但习惯、打卡和积分数据只留在每个使用者自己的浏览器中。不同设备不会自动同步。

## 视觉系统（1.4）

暖米白 `#F6F4EF`、苔藓绿 `#66735F` 与低饱和灰色；标题与数字带有记录册的排版节奏，正文和功能文字保持清晰。桌面采用顶部导航，手机采用固定底部导航，表单在手机上显示为底部 Sheet。

- Today 直接展示日期、今日完成情况和习惯列表，本周记录作为辅助信息。各习惯的独立周期、日期与进度可在展开记录或详情查看。首次使用保持空白，不加入演示数据。
- 习惯为开放列表，细线分隔、圆形打卡、单次积分；展开视图同样不使用独立卡片。详情页保留完整周期规则、本周补卡、最近记录及归档操作，增加直接打卡入口。
- History 按结束年份分组，以期数、日期、完成率和记录数排列为年鉴式列表。目标、奖励、设置和所有表单沿用同一套色彩与细线进度。
- 继续使用原本的 localStorage 键和 v4 数据格式，不迁移或改写现有业务记录。离线缓存版本随构建内容自动生成。

日期字段使用同一套应用内日历，不调用系统日期弹窗。支持年月快速切换、今天、选中日、方向键导航和 Escape 收起。周期日期沿用现有最早日期、时长联动与提交校验；目标截止日期支持清除。新日历模块随离线资源一起缓存。

图标统一使用 24 × 24 画布与 1.5px 单色描边。导航图标独立于习惯类型，今日使用日历，习惯使用记录册，目标使用旗帜，历程使用回溯符号；40 个习惯图标保留原有标识和含义，只更新图形。日历、操作、关闭按钮与应用图标沿用同一套细线语言。

## 清除本地数据（1.5）

数据与设置底部可清除本地数据。确认弹窗说明清除范围并提供先导出备份入口；只有点击「确认清除」后才删除本应用记录和显示偏好，回到首次使用的空白状态。已导出的文件、离线应用资源与同源其他应用的存储不受影响。存储访问失败时提示错误，不显示清除成功；如果另一个页面刚更新数据，需要重新确认。其他已打开页面会同步清空，清除后仍可新建习惯或导入备份。

## 今日快速列表

快速视图隐藏已完成本周目标的习惯，详细视图保留全部进行中的周期。按每天、指定星期或每周次数的实际周目标判断，首尾不足一周也使用实际目标；本周没有执行计划不视为已完成。完成最后一次、撤销今日打卡、补卡及周一换周后立即重新计算，不修改习惯状态或记录。快速列表显示剩余数量，并提供前往详细视图的入口；全部完成时显示完成提示。

## 今日必打与可选（1.6）

- 每日和指定星期的习惯，在执行日为「今日必打」。每周 X 次按本周还需执行的次数与含今天的剩余可执行天数比较：次数少于天数为「今日可选」，相等为「今日必打」，超过为「进度落后」，达到本周目标后为「本周已达标」。未来周期、到期周期和休息日分别显示对应状态。
- 首尾不足一周使用实际周目标；剩余日期截止于本周日或周期结束日中的较早日期。过去可补卡的日期不计作未来执行机会。进度落后时展示差额，允许继续打卡和补记已完成的记录，不提前判定周期失败。
- 今日打卡后统一显示「今日已完成」。是否属于今日必打按今天之前的记录推算，避免打卡后必打进度的分母缩小；撤销、补卡、跨日和周一换周都会重新计算。顶部只将必打项计入完成比例，可选和落后待处理项另行显示。
- 快速列表、展开记录和详情页使用同一套状态。所有提示实时推导，不修改周期规则、历史记录、积分或 v4 备份格式。

## 本期备注（1.7）

开始新的一期时可填写最多 200 字的备注，例如早睡模板的本期约定为「十二点半前」，下一期为「十二点前」。备注属于各个周期，不写入模板或习惯快照；下一期默认留空，归档后随原周期保留。快速列表显示最多两行，展开记录、详情和历史可回看完整内容。备注以纯文本保存，支持换行；导出与导入会保留备注，旧版没有备注的 v4 备份继续兼容。备注不参与打卡、达标或积分计算。
